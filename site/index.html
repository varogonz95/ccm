Every Claude Code session on every machine, one terminal.

Start claude on your desktop from your laptop, leave it working, and attach again from anywhere on your network. ccm is a single binary for Windows, Linux and macOS.

Set up in five minutes View source
laptop: ~

An agent on each machine, a hub wherever you are.

The same binary plays both parts.

ccm agent

Runs on each machine that hosts sessions. It keeps claude running inside a terminal of its own, so a session carries on after you disconnect, and remembers recent output for when you come back.

ccm ls, new, attach, kill

Run from any terminal. They read your list of machines and talk to each agent over your LAN. Attaching takes over your terminal; Ctrl+] hands it back and leaves claude running.

Get running

Build from source with Go 1.22+, or with Docker if you'd rather not install Go.

  1. Build every platform

    Binaries for Windows, Linux and macOS land in dist/.

    git clone https://github.com/varogonz95/ccm.git && cd ccm
make dist            # or: make docker-dist

  2. Start an agent on each machine

    It listens on port 7420 and creates a token on first run.

    ccm agent
ccm token            # print it

  3. List your machines

    On the machine you drive from, add each agent to hosts.toml. ccm help shows where it goes.

    [[host]]
name = "desk"
url = "http://192.168.1.20:7420"
token = "paste-token-from-desk"

  4. Start a session and attach

    Anything after -- is passed to claude.

    ccm new desk --dir ~/src/api -- --resume
ccm attach desk/8158   # an ID prefix is enough

Before you rely on it

A token lets its holder run claude on that machine

Traffic is plain HTTP, so keep agents on a network you trust. Agents only ever run the claude executable they were started with; the API can add arguments but can't choose the program.

Read the security notes

What doesn't work yet

  • Only sessions started through ccm show up, not claude launched in a plain terminal.
  • Stopping an agent stops its sessions. claude --resume recovers the conversation.
  • Status is running or exited. Working, idle and needs-input are next on the roadmap.
